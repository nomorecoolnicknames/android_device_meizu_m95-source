# Proprietary blob inventory — Meizu MX6 (m95, MT6797), LineageOS 20.
#
# Provenance of every file: the stock Flyme 8.0.5.0A system image
# (Android 7.1.1 / NMF26O, from MX6-flyme-8.0.5.0-update.zip,
# sha256 b77e4a14...), extracted with sdat2img; see
# meizu_mx6_m95/DEVICE_FACTS.md "Blobs".  The list itself is the DT_NEEDED
# closure computed in the 16.0 port (tools/blob-symdiff.py +
# tools/blob-needcheck.py over 710/728 ELFs), carried forward through 18.1.
#
# Syntax is LineageOS extract_utils "src[:dst]":
#   * "vendor/..."          -> stock /system/vendor/..., installed to /vendor/...
#   * "system/x:vendor/x"   -> lived in stock /system, but belongs on OUR vendor
#     partition (the stock ROM has no vendor partition at all: the stock scatter
#     declares zero `vendor` entries and the blobs sit in /system/vendor).
#   * "system/..."          -> stays on the system partition.
#
# !! READ BEFORE RE-EXTRACTING !!
# The blob tree that this port actually builds from
# (vendor/meizu/m95/proprietary) is NOT a clean extract_utils output: ~30 files
# that came from stock /system/{bin,lib,lib64} are stored at the top level of
# proprietary/ rather than under proprietary/vendor/, and several blobs are
# byte-patched (sensors multi-HAL hals.conf path, librilmtk soname rename,
# camera checkStream).  vendor/meizu/m95/m95-vendor.mk is hand-maintained to
# match that layout and to keep the lights.mt6797 blob copy OUT of the image.
# A plain `./extract-files.sh` will produce a self-consistent but DIFFERENT
# layout and will lose the patches.  See M95_LOS20_TREE.md.
#
# Two known traps from the 16.0 extraction, still true:
#   * sdat2img stores symlinks as TEXT files; always `file` a blob before
#     shipping it (hit on keystore/gatekeeper .mt6797/.mz6797_6m_n and on
#     vulkan.mt6797.so, which is why Android.mk recreates that symlink).
#   * an earlier 860-entry inventory silently missed vendor/lib{,64}/egl/
#     (libGLES_mali.so — no GPU without it), the Trustonic trustlets in
#     vendor/app/mcRegistry/ and the Meizu camera / Goodix libs that live in
#     /system/lib{,64}.
#
# BLOB AUDIT 2026-09-16 (fleet hygiene pass): NOTHING REMOVED — and that is a
# measured result, not an omission.
#
# QUESTION ASKED: which line of this list names a file that Android 13 builds
# from source and would therefore be silently overridden by a PRODUCT_COPY_FILES
# rule (copy rule from build/make/core/Makefile:72 beats the module rule in
# base_rules.mk:533 / installs-<product>.mk)?
#
# METHOD (reproducible): all 906 distinct destinations of this list were
# intersected with every install destination Soong wrote for this product,
# <original-workspace>/los20-out/out-m95/soong/installs-lineage_m95.mk (36592
# destinations, from the m95 build of 2026-09-16); then the same was done by
# BASENAME, to catch a blob that shadows an A13 module sitting in a different
# directory.
#
# RESULT — exactly one destination is shared, in both bitnesses:
#   vendor/lib{,64}/hw/fingerprint.default.so
#     A13 builds hardware/libhardware/modules/fingerprint/fingerprint.default
#     into that path (installs-lineage_m95.mk:90562,90566), and kati confirms
#     the collision out loud: "overriding commands for target
#     .../vendor/lib64/hw/fingerprint.default.so" in
#     <original-workspace>/meizu-fleet/build-m95.log — the ONLY such warning in
#     that whole log.
#     THE BLOB STAYS.  FACT: proprietary/lib{,64}/hw/fingerprint.default.so is
#     the Goodix vendor HAL — .name "Goodix Fingerprint HAL", DT_NEEDED
#     libgf_hal.so / libgf_ca.so / libgoodixfingerprintd_binder.so, built with
#     "GCC: (GNU) 4.9 20150123 (prerelease)".  AOSP's fingerprint.default is
#     the "Demo Fingerprint HAL" (hardware/libhardware/modules/fingerprint/
#     fingerprint.c:120) and does nothing.  So this is the one collision we
#     want, in the same sense as power.default.so on the m5c.
#
# NEAR MISSES, checked and deliberately left alone:
#   vendor/lib/libbt-vendor.so — device/meizu/m95/shims builds
#     libm95shim_btvendor into vendor/lib64/libbt-vendor.so, 64-bit ONLY; this
#     blob line is the 32-bit file.  They do not collide today.  HYPOTHESIS: if
#     the shim ever grows a 32-bit variant the winner becomes makefile order —
#     drop this line at that moment.
#   vendor/lib{,64}/liblogwrap.so — A13 builds system/logging/logwrapper into
#     system/lib{,64}/liblogwrap.so and into the ramdisk, never into /vendor.
#     The /vendor copy is the same class of deliberate second copy as
#     libbinder.so / libnetutils.so (M95_LOS20_TREE.md §"второй libbinder"),
#     which that report declares mandatory.  Not touched.
#   vendor/etc/security/cacerts_supl/594f1775.0 — A13 ships a file of the same
#     name under system/etc/security/cacerts_google/.  Different directory,
#     different consumer (SUPL); no collision.
#
# WHAT WAS *NOT* CHECKED HERE (honest gap): this intersection sees Soong
# modules and the kati warnings of a real build.  A module declared only in an
# Android.mk of an unrelated tree and not reached by this product's kati pass
# would not show up.  For this workspace that gap is covered by the fact that
# the m95 build log contains exactly one overriding-commands warning.

# Files that ARE in vendor/meizu/m95/proprietary/ but are deliberately NOT in
# the list above (verified 2026-09-16 by diffing the blob tree against this
# file; 920 files on disk, 902 listed, 18 exceptions, no unexplained ones):
#
#   vendor/lib{,64}/hw/lights.mt6797.so
#       The blob cannot work on this device (red/green/blue/button-backlight
#       sysfs nodes are absent) — lights.mt6797 is built from source in
#       device/meizu/m95/lights/.  A copy rule here would OVERWRITE the built
#       module in the image, because copy rules are emitted after module rules.
#   vendor/lib{,64}/hw/audio.r_submix.mt6797.so, audio.usb.mt6797.so
#       Replaced by the AOSP audio.r_submix.default / audio.usb.default modules.
#   vendor/lib{,64}/libperfservicenative.so
#       Replaced by the device shim libm95shim_perfservice (stem
#       libperfservicenative), device/meizu/m95/shims/perfservice.c.
#   vendor/lib{,64}/libbinder.so, libnetutils.so
#       Not stock blobs: these are VNDK v30 libraries taken from this port's own
#       Android 11 build.  They are copied by device.mk, not from here, with the
#       sphal-namespace reasoning written next to the copy rule.
#   vendor/lib{,64}/libnativehelper.so
#       Same kind of thing (our own R build), copied by m95-vendor-extra.mk into
#       /vendor/lib{,64}/hw so the SYSTEM default namespace cannot see it.
#   vendor/lib64/librilimp.so
